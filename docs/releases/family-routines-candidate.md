# Calden — Family routines integrated development candidate

Status: **Committed source work, not a tested production release.** This addition extends the existing Calden 1.4.8 foundation without changing its published version, deployment shape, calendar models, reminders or bill histories.

## User functionality

- Household administrators and planners can enable Routines in Settings -> Optional Features.
- Once enabled, a dedicated addressable `/routines` page becomes available.
- Authorized household administrators/planners can create morning, evening and anytime checklists for active family members.
- Each routine supports selectable weekdays, an optional note and 1–30 editable, ordered checklist steps.
- Assigned members can mark their own steps completed on a scheduled day. Administrators/planners may assist with household checklists.
- Lists show per-routine and daily completion progress for the selected date.
- Existing step IDs are maintained when a routine is edited. An edited or removed step does not erase prior completion records.
- Archiving a routine removes it from active views, not from stored completion history.
- A `routines` widget can be selected on My home, and is hidden when the module is disabled, without deleting the preference.

## Backend and security model

- Migration `031_family_routines.sql` creates `family_routines` and `family_routine_progress`, with foreign keys, unique per-step/per-person/per-day progress, weekday check constraints and indexes.
- `routines_enabled` defaults to false to avoid presenting an unaccepted feature automatically. Disabling it does not touch persistent data.
- All endpoints use Calden's existing authenticated middleware, existing user roles and the shared household settings.
- Only `admin` and `planner` may create, edit or archive routines. Ordinary and restricted family members can only see and update their own assigned checklists.
- Step IDs are generated by the server and checked against the prior routine on modification. Foreign/duplicate IDs are rejected.
- Attempts to update an unscheduled day, a non-existent step, an archived routine, or a date outside the bounded window are rejected.
- Completion is idempotent using a composite primary key and `ON CONFLICT DO NOTHING`. The completion history survives configuration edits and archive.
- Audit records identify routine configuration changes and checklist updates.

## HTTP API

- `GET /api/routines?date=YYYY-MM-DD` -> `{date,items:[...]}`
- `POST /api/routines` (admin/planner)
- `PUT /api/routines/{id}` (admin/planner)
- `DELETE /api/routines/{id}` -> archive, without destroying progress (admin/planner)
- `PUT /api/routines/{id}/steps/{step_id}/status` -> `{"date":"YYYY-MM-DD","completed":true|false}`

Example create payload:

```json
{
  "title":"Before school",
  "notes":"Get ready for the day",
  "assigned_to":"a-real-user-uuid",
  "time_of_day":"morning",
  "days_of_week":[1,2,3,4,5],
  "steps":[{"title":"Brush teeth"},{"title":"Pack backpack"}]
}
```

Weekdays are ISO 1=Monday through 7=Sunday. GET returns stable step IDs required for edits and completion updates.

## Verification and release gate

Source-level JavaScript syntax, route IDs, feature authorization wiring and recurrence/step validation checks can be performed without a running database. Production acceptance **requires**:

1. `go test ./...` with Go 1.24+ and the project's dependencies.
2. `npm install --no-audit --no-fund && npm run build:css && npm run test:web`.
3. Database migration on a restored copy of an existing installation, then multiple install/backup/restore/restart cycles.
4. HTTP integration tests with administrator, planner, member and restricted accounts; unauthorized assignment, stale step IDs, concurrent completion requests, archived routines and disabled-module requests.
5. Browser interaction tests for adding, editing, moving, removing and completing steps, including narrow screens, refresh, private information, dark appearance, keyboard operation and time-zone boundaries.
6. Android compatibility and end-to-end notification acceptance. **Routines do not yet generate Android or Monita reminders** and should not be advertised as doing so.
7. Sign-off, release notes, updated version/cache keys and deployment validation before a stable tag.

This module is a subset of [the full approved expansion](../FAMILY-PLATFORM-EXPANSION.md), not evidence that the entire family platform has shipped.
