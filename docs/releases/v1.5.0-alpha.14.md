# Calden v1.5.0-alpha.14 — Reliable Self-Recovery and Carrier Scheduling

This release builds on the published v1.5.0-alpha.13 portable engine and preserves the stable product baseline.

## Integrated changes
- Do not download a roughly 800 MB tracking runtime until Package Tracking is actually enabled; enabling it starts background recovery without a container restart.
- Automatic recovery attempts use a ten-minute retry delay after failure rather than repeatedly downloading a large archive every 30 seconds.
- While recovering, manual tracking requests return an accepted/pending repair state. They do not consume the manual two-minute cooldown or record an imaginary failed carrier scan.
- Scheduled three-hour scans wait until the local tracking engine is ready instead of claiming jobs and hiding shipments for three hours.
- Successful recovery re-queues all active shipments, including those with older carrier-verified status.
- The Packages page automatically refreshes recovery status and tracking data; its manual tracking controls display a disabled **Preparing tracker** state while recovery is underway.
- API, PostgreSQL, and JavaScript regression tests check feature opt-in, repair-pending handling, manual cooldown preservation, and scheduler behavior.

## Compatibility and safety
The alpha.14 self-repair bundle is version-pinned, checksum-verified, size-limited, extracted under the existing persistent data directory and executed without root or a Docker socket. The release also builds the full multi-architecture Docker image. Preserve the existing database and application volumes through any upgrade.

## Acceptance boundaries
CI and non-root Alpine portable runtime checks are required to publish. Live carrier status from arbitrary public websites, an actual legacy-container upgrade on the user's host, and Gmail/Outlook OAuth remain **unverified or outstanding**. No successful carrier event is invented when a provider blocks access.
