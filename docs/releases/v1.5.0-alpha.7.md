# Calden 1.5.0-alpha.7 — Public Tracking Without API Keys

This release continues **1.5.0-alpha.6** on the existing 1.5 alpha track. It retains household settings, calendars, meal planning, RecipeCove, saved package history, and the existing Postgres data volume.

## What changed

- **No AfterShip API key required** for the default Package Tracking workflow. Adding a package triggers a keyless check of the relevant **official carrier public tracking page**.
- Automatic tracking checks are queued and retried approximately **every three hours** for undelivered, unarchived packages. The schedule persists in PostgreSQL.
- A conservative HTML parser only records a status when an official carrier page visibly shows the exact tracking number with an unambiguous status indication. It never invents carrier scans or infers statuses from generic template words, JavaScript snippets, or bot challenges.
- When a public page is interactive, unavailable, inaccessible, or requires customer authentication, Calden **keeps the package** and displays “Live status is not available from this carrier's public page,” along with its official **Track with carrier** link. Saving packages never demands an API key.
- If an authorized AfterShip integration is already configured, it remains available as an **optional advanced integration**; disabling or disconnecting it reverts to keyless public attempts.
- Calendar projections, household sharing, email discovery, package history, and alpha 1.5 functionality remain unchanged.

## Reality of public carrier websites

**A public tracking webpage is not a public tracking API.** Some carriers render shipment results only after scripts, cookies, account login, or human verification. Their sites may return no safely readable status to an unattended Go server. Therefore, **this feature is best-effort and cannot guarantee live status updates without authorized carrier access**. The app reports that limitation clearly rather than pretending a lookup succeeded.

USPS restricted automated tracking data access in April 2026; legacy Web Tools was retired in January 2026. Amazon Logistics' detailed TBA tracking generally requires the customer's order information and is not available through an unrestricted tracking API. Calden does not bypass CAPTCHAs, carrier access controls, authentication, or bot checks.

## Verification and upgrade

- New tests check official tracking-host restrictions, visible shipment-number requirements, status matching, and deliberate rejection of generic status text or challenge responses.
- Go, PostgreSQL migration, JS and web regressions run in CI, with signed release artifacts for Linux AMD64/ARM64 and an isolated Docker tag.
- Upgrade the existing 1.5 alpha installation in place, retaining its persistent database and data volume. Back up data before testing alpha builds.
- Docker image: `ghcr.io/gigabytegrove/calden:1.5.0-alpha.7`.

This release does not claim successful authenticated API polling or guaranteed carrier status data from public sites. Test live source availability with a real shipment before relying on it.
