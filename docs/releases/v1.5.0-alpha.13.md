# Calden v1.5.0-alpha.13 — Automatic Tracking Runtime Repair

The package-tracking engine is a Calden responsibility, not a deployment task for each household.

## Self-healing from older Docker images

Calden now checks for its bundled Node.js/Chromium tracking engine on startup. On older Alpine-based images that were updated in-app without a full container replacement, Calden automatically downloads the release's **musl-compatible AMD64 or ARM64 tracker runtime**, verifies its SHA-256 checksum, unpacks it into the existing Calden persistent data volume, tests the tracking CLI offline, and activates it as the regular unprivileged Calden user. It retries transient download failures without user intervention and schedules pending unverified packages for fresh scans after a successful repair.

No Docker socket, root privileges, new service, paid API key, npm commands, image rebuild, environment variable, or additional Docker volume is required. Existing PostgreSQL and household data are preserved. The repair assets are shipped by the same Calden GitHub release alongside the updater binaries.

**Not an arbitrary installer:** Calden fetches only fixed, version-pinned GitHub release assets, restricts redirect hosts, validates checksums, enforces compressed/uncompressed size limits, rejects path escapes/symlinks/special files, and activates a runtime only after it passes an offline carrier-detection probe. Failed or interrupted repairs leave the previous runtime untouched.

## Package Tracking UX

The Packages screen reports automatic repair progress instead of telling the user to install missing software. Manual carrier checks remain available independently of the three-hour background scheduler. Real carrier data still depends on public sources responding with verifiable shipment status; Calden never fabricates delivery events.

## Verification

The publish workflow runs Go and PostgreSQL tests, JavaScript tests, both binary archive builds, creates both portable tracking runtime bundles, and verifies that the AMD64 recovery bundle runs as a non-root user in the old Alpine image before pushing multi-platform Docker images and publishing the release.
