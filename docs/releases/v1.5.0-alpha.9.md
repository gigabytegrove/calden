# Calden 1.5.0-alpha.9 — Free Local Package Tracking Hardening

This continues the **Calden 1.5 alpha** line and preserves the dashboard, calendars, Meal Planning, RecipeCove, household accounts, package history, and all existing database volumes.

## What the household sees

1. An administrator enables **Settings → Optional Features → Package Tracking**.
2. Enter a tracking number. Calden recognizes likely carriers (UPS, USPS, FedEx, Amazon and others), saves the package and attempts an automatic carrier lookup **in the background**.
3. Real carrier status, scan descriptions, known facility/location and ETA appear directly in the Packages list and full shipment history when returned by supported sources.
4. Undelivered shipments are checked by the existing server-side scheduler approximately every **three hours**, including after a restart. Delivered or archived shipments stop polling.
5. No AfterShip subscription, account, API key, separate API service, extra Docker sidecar, or developer signup is needed.

The engine is [Universal Parcel Scraper](https://github.com/plhery/universal-parcel-scraper) **0.637.1** (Apache-2.0 with bundled LICENSE and NOTICE), with Node.js 26, Chromium, HTTP/browser carrier adapters, and free public fallback sources. Everything runs **inside the same Calden application Docker image**. Calden's existing PostgreSQL service remains the database.

## Additional fixes since alpha.8

- Correctly handles upstream `registered`, `accepted`, `customs`, and `ready_for_pickup` statuses, including in-transit and label-created conversions.
- Prevents unrelated tracking-number responses from overwriting a household shipment.
- Records real carrier scan event times and locations with deduplication. Unzoned local carrier times are not silently treated as UTC.
- Uses a strict allowlist of environment variables passed to the embedded Node subprocess, preventing Calden database, JWT, SMTP, and other secrets from leaking into tracking adapters.
- Adds a full Node → Go → PostgreSQL integration test proving actual status, ETA, facility display and idempotent event history, plus additional security/unit tests.
- Hides the optional legacy paid-provider API setup from the normal Packages interface, updates user-facing guidance, and repairs the server CI asset-version checks that were still pinned to v1.4.7.

## Installing or updating

Use the **complete Docker image** `ghcr.io/gigabytegrove/calden:1.5.0-alpha.9` with the same existing Compose or Dokploy deployment and **the same persistent database and data volumes**. Back up the alpha database before upgrading. No new tracking-specific environment variables or secrets are needed.

**Important:** The portable Go-only runtime archives published by older releases do not contain the Node.js + Chromium tracking engine. This release is **Docker-first**; updating a Go binary alone would not supply full free carrier tracking. Pull the complete image.

## Data sources and limits

Carriers sometimes block or change public tracking pages or require recipient-specific details. This implementation cannot promise successful live scans for every UPS, USPS, FedEx or Amazon tracking number. Amazon Logistics TBA shipments may require a signed-in Amazon customer account. Calden **never fabricates scans or delivery dates**; it preserves the last verified information and schedules another check when a source provides no updates.

Public fallback services (ParcelsApp, Ship24, 17TRACK, Postal Ninja, UPU) may receive the tracking number in addition to the carrier. They require no household subscription or account. The engine makes outbound HTTPS requests to access public tracking data; it is not a completely offline service.

The Docker build and integration tests are automated; real-world coverage depends on carriers and should be validated using actual shipments. See `docs/PACKAGE_TRACKING.md` for detailed operations and privacy information.
