# CalDen 0.1.0-alpha9

This release turns notifications into a real product feature, makes categories actually deletable, and gives the web application a much stronger Tailwind-backed visual system.

## Event assignment notifications

Creating an event in CalDen now creates persistent alerts automatically.

- If one or more people are assigned to the event, each assigned person gets an **Assigned to you** notification.
- If nobody is assigned, CalDen treats the event as applying to everyone and creates a **For everyone** notification for every active user who can see that calendar.
- Notifications persist in the database, so they are still there the next time that person signs in.
- The Notifications page now has a real inbox above scheduled reminders.
- Unread alerts produce a badge in the main navigation.
- Notifications can be marked individually or all at once.
- Users can opt in to native browser notifications. When enabled, a signed-in browser polls for new alerts and shows them without losing the persistent in-app copy.
- Bulk Google/iCalendar migration does not create thousands of assignment alerts. These alerts are intentionally generated by normal CalDen event creation.

## Category deletion

Categories are no longer archive-only.

- **Delete category** permanently removes the category.
- CalDen shows how many events currently use it before confirmation.
- Existing events are preserved. PostgreSQL clears their category reference, so they simply become uncategorized.
- Calendar ownership, event color, reminders, assignees, bills, and recurrence data are untouched.

## Tailwind CSS and UI/UX

The web UI now has a real Tailwind CSS v4 build pipeline instead of relying only on a growing hand-written stylesheet.

- Tailwind CSS 4.3.3 and its CLI are pinned in the repository.
- Docker builds compile the Tailwind bundle automatically.
- GitHub release bundles compile the same CSS before packaging.
- Direct source development can run `npm install && npm run build:css`.
- The existing component stylesheet is compiled into the Tailwind layer stack, allowing the interface to move gradually instead of being rewritten all at once.

The visible application shell received a full design pass:

- dark slate navigation rail with iconography and a stronger active state
- proper logo treatment in the sidebar and authentication screen so the transparent logo is visible
- stronger page hierarchy and spacing
- modern rounded panels, controls, inputs, dialogs, and hover/focus states
- improved agenda cards
- redesigned notification inbox
- cleaner responsive behavior
- retained calendar colors and the restrained family-calendar visual language rather than turning the app into a generic admin template

## Validation

CI now verifies:

- the Tailwind-backed shell is actually being served in Chromium
- the official logo asset loads in the sidebar
- creating an assigned event creates the assignee's persistent notification
- creating an unassigned event on a shared calendar creates the whole-family notification
- unread counts and mark-read behavior
- the notification inbox is visible in the browser
- categories can be permanently deleted from the browser
- existing recurring-event, Bill Pay, Google migration, iCalendar, backup/restore, calendar destructive-delete, and Docker Raw deployment tests remain enabled
