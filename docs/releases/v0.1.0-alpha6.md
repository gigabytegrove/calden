# CalDen 0.1.0-alpha6

> **Historical Google-import note:** This release predates Alpha11's cross-calendar duplicate repair. Re-import behavior described below did not prevent every duplicate row that could be created from Google Takeout data. For current migration and repair behavior, see `docs/GOOGLE_CALENDAR.md`.


This release keeps the current CalDen direction intact and focuses on migration, visual refinement, and a few pieces of reliability that matter in daily use.

## Google Calendar migration

- New Google Calendar migration workflow under Integrations
- Import the ZIP exported by Google Calendar in one pass
- A single .ics file can also be imported through the same migration workflow
- Creates matching CalDen calendars automatically
- Can reuse an existing CalDen calendar when the names match
- Re-importing the same Google export updates previously imported events instead of duplicating them
- Multi-calendar imports are processed together and return a per-calendar import report
- Recurring events, recurrence exceptions, all-day events, notes, locations, and supported calendar metadata flow through the existing iCalendar importer
- Original RFC 5545 recurrence rules are retained so advanced Google repeat patterns are not silently simplified
- Imported advanced recurrence rules stay intact when ordinary event details are edited unless the repeat controls are intentionally changed

## Interface polish

- Refined application spacing, depth, borders, and visual hierarchy without changing CalDen's established design
- Cleaner sidebar active state and account area
- More polished calendar toolbar, filter bar, calendar chips, event cards, agenda rows, and management cards
- Improved panel and settings presentation
- Integrations is now a full workspace with a dedicated Google migration card and clearer Monita configuration
- Google migration includes drag-and-drop, file summary, progress/status, and import results

## Profile images

- Profile image upload limit increased from 4 MB to 10 MB
- Fixed broken local profile-image previews caused by the Content Security Policy blocking blob URLs
- Added browser-side file-size validation before a user is created or an upload is attempted
- Avatar responses now revalidate instead of remaining stale in the browser after an image is replaced
- Profile-image help text now consistently reflects the 10 MB limit

## Recurrence reliability

- CalDen can now retain and expand advanced RFC 5545 recurrence rules used by imported calendars
- Advanced recurrence rules are preserved on iCalendar export
- Reminder scheduling and occurrence validation understand preserved imported recurrence rules
- Added unit coverage for first-Monday style monthly recurrence and Google Calendar ZIP parsing

## Validation and packaging

- Browser CI now verifies that a selected profile image actually renders in the live preview
- Browser CI verifies the Google Calendar migration interface is present
- End-to-end CI verifies multi-calendar Google ZIP import, repeat import without duplicates, and advanced recurrence expansion
- Container publishing now uses the actual VERSION file instead of the stale hard-coded alpha1 image tag
- Development fallback version updated to alpha6

## Android

Android work remains intentionally parked while the web application is completed and stabilized.
