# Calden 1.3.7 — Fix payment labels on appointments

## Server-side correction
- Only events in calendars explicitly classified as `bill_pay` receive bill amount, payment status, allocation, payment history, and payer fields.
- Ordinary calendar events and appointments no longer receive an artificial `bill_payment_status: "due"` value.
- The same classification is applied to recurring event series and their overridden individual occurrences.
- The event API now identifies each event's `calendar_type`, including replacement and parent calendar types for recurring exceptions.
- CI tests assert that ordinary and recurring appointments have no bill payment fields while real bills retain the correct `due` status.

## Android coordination
Calden Android 1.3.7 also prevents old server data from producing payment labels on appointments by checking the event's calendar type instead of just checking whether payment fields are populated.

This is a display/data classification correction; existing bill records and event data are not deleted or migrated.
