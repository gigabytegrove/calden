# Calden v1.5.0-alpha.12 — Carrier Tracking Runtime Diagnosis and Manual Refresh

## Fixed
- **No more false carrier-page dead ends.** When the bundled Node.js/Chromium tracker is absent, Calden identifies the missing local runtime rather than showing a generic "Track with carrier" response.
- **Runtime health displayed in Packages.** Calden performs an offline readiness check: the bundled parcel CLI, Node.js executable, and Chromium availability. Missing or degraded components show an actionable message on the Packages screen without exposing tracking numbers.
- **Check tracking now is an actual manual check.** Previous versions incorrectly used the three-hour scheduled claim for button presses. Manual checks now run independently with a two-minute cooldown to prevent accidental rapid repeated carrier requests. The background scheduler continues every three hours.
- **No fabricated carrier results.** Site access restrictions or absent scans leave existing verified history intact. The public-page fallback now reports a failed verification and automatic retry, rather than instructing users to leave the application.

## Important: complete tracking runtime
Calden's Linux binary in-app updater changes the Go server and web UI. It **cannot replace the underlying Docker image**, so it cannot install Chromium or Node.js into an older container that lacks them. To supply the tracking engine, deploy the **complete Docker image** `ghcr.io/gigabytegrove/calden:1.5.0-alpha.12` while retaining the original database and persistent volumes. This needs to be done once on pre-tracker installations. The complete image contains the bundled Node 26, Chromium, and Universal Parcel Scraper; users do not need API keys or a second tracking service.

Some carriers restrict unauthenticated tracking or require extra data. These conditions cannot be bypassed by Calden and are not represented as successful scans.

## Regression gates
Go unit and PostgreSQL integration tests cover the manual check cooldown, scheduled tracking, and missing-runtime diagnostics. Web tests cover the visible health banner and no-dead-end behavior. The release publisher builds checksum-verified AMD64 and ARM64 binary update archives, and multi-architecture full Docker images.
