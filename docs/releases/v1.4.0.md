# Calden server 1.4.0 — Notifications, Conflicts and Monita

## Notifications

- Durable FCM HTTP v1 outbox: one idempotent delivery per notification/device.
- Atomic delivery leases, bounded exponential retry, cleanup of invalid FCM tokens.
- Encrypted device token registration, renewal and per-account revocation.
- Account-specific payloads (recipient ID), minimal message data, deduplicated in Android.
- Native push is **opt-in**. WebSocket notifications and WorkManager catch-up remain
  available when native push is not configured.
- Server-side bill review generation every two minutes so overdue payment prompts
  don't rely on opening the app.
- Shared appointments with no assignees notify authorized household members when
  updated or cancelled. Recurring-instance alert improvements remain in place.
- Monita reminder sends now use atomic leases, bounded retries and backoff.

### Native FCM configuration
To enable native background push, supply ALL of these to the Calden server:
- `CALDEN_FCM_SERVICE_ACCOUNT_FILE`: path to a mounted JSON Firebase service
  account, readable only by the server process and with permissions 0600.
- `CALDEN_FCM_PROJECT_ID`: Firebase project ID matching the JSON credentials.
- `CALDEN_FCM_SENDER_ID`: Firebase Cloud Messaging sender ID.
- `CALDEN_FCM_ANDROID_APP_ID`: Android Firebase application ID.
- `CALDEN_FCM_API_KEY`: Firebase Android API key (public client identifier).

The server performs OAuth service-account authorization. Do **not** provide
service-account credentials to Android clients or place them in GitHub.
The Android app requests only public Firebase client configuration after Calden
authentication and registers its device token. Configuring the server does not
prove actual push delivery until tested on physical Android phones.

## Scheduling conflicts
- Half-open interval overlap checks, shared-calendar/assigned-person detection,
  recurring event expansion and suppression of cancelled/rescheduled instances.
- Private per-user busy blocks. Other users see a generic busy conflict, never
  the private label or a person's private notes.
- Confirmation before saving overlaps; **Save anyway** is an explicit user choice.
- All-day events and Bill Pay entries retain their existing editing behavior.
- Planner/admin visibility differs from ordinary member visibility.
- API supports a 90-day forward recurrence preview and up to 100 findings, not
  an unlimited future recurrence guarantee.

## Monita
- Connect and verify service-account credentials against authorized channel
  discovery, then test publishing and securely store the token.
- Explicit disconnect disables Monita and clears the credential.
- Existing legacy token behavior is retained for installations using it.
- Monita remains the family-channel delivery integration, separate from per-user
  Android notifications.

## Validation policy
Both server and Android source are coordinated as 1.4.0. A passing server CI
checks implementation correctness and fresh database migrations; a successful
Android Gradle build, installed-phone tests, valid FCM credentials and a
Monita-connected test are separate release acceptance criteria. Do not mark
those completed until evidence is available.
