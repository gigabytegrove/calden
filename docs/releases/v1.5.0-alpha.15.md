# Calden v1.5.0-alpha.15 — UI Consistency and Shipment Tracking History

## Functional delivery
- **Tracking history is directly accessible.** Every visible package has a Tracking history button, including shared packages a member may view but not edit. The package editor also offers a dedicated History action.
- A separate, accessible timeline shows recorded carrier events, locations/details, timestamps and their actual source. User-created and email-imported records are never presented as verified carrier scans. History has real loading, empty, retry and failure states.
- The server paginates tracking history securely in batches of 100 with deterministic ordering and a **Show older activity** control rather than silently truncating larger histories. Package owner/share permissions continue to apply before any checkpoint query.
- **A single web UI contract** standardizes cards, form controls, buttons, status indicators, settings, bill ledgers, integrations, family modules, dialogs and mobile action layouts using the approved Calden design. Calendar colors, member avatars, existing light/dark preferences and household palette identity are preserved.
- Tailwind v4 scans the newer Packages and Meals modules as production class sources.

## Qualification
- The release source includes JavaScript/DOM tests for opening history, shared read-only viewing and loading subsequent pages, a CSS build check, and a real Chromium visual contract for 360px, 768px and 1280px light/dark appearances.
- The release pipeline runs Go tests, web tests, Alpine portable-runtime compatibility tests, a complete image build and registry publication, and verifies all release archive hashes.

## Runtime compatibility
The tracking engine has **not changed** since alpha.14: `parcelRuntimeTag` intentionally remains pinned to the published, verified alpha.14 recovery bundle. Upgrading the interface must not force a redundant ~800 MB engine redownload. A missing engine still installs automatically using that existing verified runtime. The alpha.15 full Docker image ships the complete tracker.

## Still outstanding
The release cannot claim successful tracking on every carrier or actual operation on the user's Docker installation without end-to-end tests using live shipments. Google/Microsoft OAuth email onboarding, Android native UI parity, and unrelated P0 operational items remain open in the engineering register. This release does not fabricate a live carrier event or treat a successful CI run as a physical installation.
