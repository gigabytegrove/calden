# Calden 1.5.0-alpha.6 — Automatic Carrier Tracking

**This updates the existing Calden 1.5 alpha track.** It does not replace the alpha UI, household data, Meal Planning, RecipeCove, or any previous package records.

## What changed

- Enter a tracking number; **Auto-detect** is selected by default. Recognizable UPS, USPS, Amazon Logistics and FedEx number formats are identified locally, while the provider API confirms the courier once connected. Ambiguous numbers are not falsely labeled as verified.
- Optional household-admin **Tracking API settings** in Packages accept an authorized AfterShip Tracking API key. Secrets are encrypted using the appliance's persistent secret and are never returned to the client.
- Registered package shipments get an immediate provider lookup when saved. A server-side scheduler subsequently checks undelivered, unarchived packages every **three hours** (checks at most five due packages per minute). The schedule is stored in PostgreSQL and survives restart.
- Fetches normalized real provider statuses, official courier IDs, ETA information and carrier scan checkpoints. Repeated scan history is deduplicated by provider event ID. The package calendar overlay moves when verified delivery estimates change.
- A package detail view shows when the last provider lookup occurred, the next check, and any safe-to-display provider error. API permissions and rate limitations are handled as errors, not fake tracking results.
- Manual carrier selection remains available when automatic detection is ambiguous. Existing shipment records remain private by default, and Package Tracking remains disabled until the admin enables it.

## Requirements and compatibility

AfterShip provides a common tracking API for supported carriers; it is an external commercial service. API access is plan-dependent and may incur fees. Enter an authorized API key in **Packages → Tracking API settings**. Do not enter UPS, FedEx, USPS, or Amazon login credentials. Configuring an AfterShip API key is necessary before Calden can retrieve carrier scans. Without it, package entry and number-format detection continue to work, but live status will remain unavailable.

Migration `044_package_tracking_provider.sql` adds encrypted provider config, per-package poll timestamps and scan IDs. It preserves migrations 041–043, existing packages, historical statuses and calendar entries. Changing provider API keys resets provider references to register active packages under the new account.

The automatic worker **attempts** lookups on a three-hour cadence; carrier data freshness, limits and error recovery depend on the external service. Completed shipments stop polling. This release does not implement personal carrier-account login or Outlook OAuth.

## Verification

CI builds and Go + web tests run against a PostgreSQL 16 test service. Real tracking and credentials must be tested with an authorized account after installation. The alpha-only release publisher produces AMD64 and ARM64 runtime archives and `ghcr.io/gigabytegrove/calden:1.5.0-alpha.6` without modifying the stable Docker `latest` tag.
