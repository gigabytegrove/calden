# CalDen 0.1.0-alpha4

CalDen 0.1.0-alpha4 continues the move from an initial calendar prototype into a complete household scheduling product.

## Repeating events

- Daily, weekly, monthly, and yearly recurrence
- Custom intervals such as every 2 weeks or every 3 months
- Multiple weekday selection for weekly schedules
- Repeat forever, through a date, or for a fixed number of occurrences
- Month-end handling for dates such as the 31st
- Leap-day handling for yearly repeats
- Recurrence is generated server-side and shared by web, Android, and reminders

## One occurrence versus the entire series

- Edit one occurrence without changing the rest of a recurring series
- Move one occurrence to a different date or time
- Change one occurrence's title, notes, location, people, calendar, category, and reminders
- Delete one occurrence without deleting the series
- Restore support at the API layer
- Changed occurrences remain associated with their parent series
- Web explicitly asks whether to edit this occurrence or the entire series
- Android uses the same occurrence/series model

## Recurring reminders

- Monita reminders are generated for every occurrence in a recurring series
- Cancelled or overridden parent occurrences no longer send the original reminder
- A moved occurrence can use its own reminder schedule
- Delivery tracking is per occurrence rather than only per reminder definition

## Event categories

Calendars and categories are now separate concepts.

Example:

- Calendar: Family
- Category: Medical
- People: Brad + Jen

Categories own the event display color. Calendar color remains available as the fallback when an event has no category.

Included:

- Dedicated Categories page
- Create, edit, and archive categories
- Category name, color, icon, and description
- Starter categories on new installations
- Event category selection in the web editor
- Category metadata in the API
- Category support on recurring occurrence overrides
- Android category loading and event selection
- Existing events without a category continue to use their calendar color


## Activity history

- Persistent server-side audit log
- Dedicated administrator Activity page
- Records event creation, edits, deletes, recurring occurrence changes, and restores
- Records people, calendar, permission, category, household setting, Monita, and updater changes
- Password values and integration tokens are never stored in activity history
- Activity can be filtered by entity type

## Reliability and validation

Automated tests now cover:

- Recurrence count and end-date behavior
- Weekly multi-day repeats
- Month-end recurrence
- Leap-day recurrence
- Creating a recurring series against PostgreSQL
- Moving one occurrence and suppressing its original generated slot
- Deleting one occurrence while preserving the series
- Preserving category metadata and category color through recurrence
- Category management in a real Chromium browser
- Persisted activity history in a real Chromium browser
- Existing first-run, People, Settings, calendar-view, Compose, and Docker Raw smoke tests

## Android

The Android source now follows the same product model for:

- 1, 7, 14, and 30 day calendar views
- Agenda
- Event creation and editing
- Recurrence
- This-occurrence versus entire-series editing
- Categories
- Household/account settings

GitHub's Android Actions runner for the private Android repository is currently failing before a runner is assigned, so Android build verification remains separate from the green server/web validation and will not be represented as verified until an actual Android compiler run completes.
