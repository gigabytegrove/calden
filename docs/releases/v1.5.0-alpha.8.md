# Calden 1.5.0-alpha.8 — Free local carrier tracking (no API key)

This build continues the **1.5 alpha line**. It preserves your calendars, Meal Planning, RecipeCove, household users, saved package records and email imports.

### The package-tracking workflow

1. A household administrator enables the optional **Package Tracking** feature (still disabled by default).
2. Anyone allowed to add packages enters a tracking number; Calden infers likely carrier from its format.
3. Calden immediately saves the package and **looks up carrier history in the background** using a bundled local, Apache-2.0 tracking engine.
4. If the carrier or public sources return real scan events, Calden stores their status, scan time, **facility/location**, scan descriptions, and estimated delivery date when available. The latest scan is visible directly in Packages; the full history appears under package details.
5. The existing PostgreSQL worker automatically requests fresh updates approximately **every three hours**, and stops polling delivered and archived shipments.

**No AfterShip key, payment, developer account, separate scraper service, or user configuration is required.**

### One-container deployment

The Calden **Docker** image bundles Node.js 26, Chromium, and [Universal Parcel Scraper](https://github.com/plhery/universal-parcel-scraper) version **0.637.1** (Apache-2.0), including its optional public aggregator fallback transports. All of this runs inside the same Calden application container; PostgreSQL remains the database service already required by Calden. No additional tracker container or hosted proxy is needed.

Deploy **`ghcr.io/gigabytegrove/calden:1.5.0-alpha.8`** through your existing Calden Compose/Dokploy configuration, retaining your existing `calden-db` and `calden-data` volumes. Back up alpha data before updating. Since this release adds native Node and Chromium dependencies, **in-place binary-only updates from an old Alpine container are not sufficient**; pull/redeploy the complete 1.5.0-alpha.8 Docker image.

### Privacy, licensing and limitations

The open-source adapter communicates directly with carriers where possible. Its configured free public aggregator fallbacks (ParcelsApp, Ship24, 17TRACK, Postal Ninja and UPU) may also receive the tracking number. No personal carrier credentials are collected. Universal Parcel Scraper's Apache-2.0 license and upstream NOTICE remain in the installed package.

**A public tracking number does not guarantee machine-readable events.** Some carriers challenge headless browsers or require account login; Amazon TBA delivery information is especially limited. Calden never invents events or parcel locations. If no credible scan can be retrieved, it preserves the last real scan and continues scheduled attempts. Upstream adapter support and testing cannot guarantee uninterrupted live carrier access. Real live-package validation remains required after installation.

See [Package Tracking](../PACKAGE_TRACKING.md) for the privacy and setup guidance.
