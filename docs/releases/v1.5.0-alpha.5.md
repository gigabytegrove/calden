# Calden v1.5.0-alpha.5 — Package Tracking in the 1.5 Alpha

This release continues **v1.5.0-alpha.4**, preserving the alpha UI, Meal Planning / RecipeCove workflows, personalizations, and their data. It is **not** a downgrade to the 1.4.x stable codebase.

## Features

- Adds opt-in **Packages** (off by default) alongside the existing alpha pages. No personal or household deliveries are exposed by default.
- Tracks UPS, USPS, FedEx, Amazon Logistics and other shipments, expected delivery dates, statuses, carrier links, history, and owner-controlled household sharing.
- Shows non-editable package overlays in the existing 1-, 7-, 14- and 30-day calendar views, with a separate calendar visibility filter. Package records do not duplicate calendar events.
- Imports bounded RFC822 shipping emails from pasted text or .eml files, deduplicates tracking numbers, and infers **tentative** delivery estimates where the email explicitly states a date.
- Provides an optional inbound email forwarding hook using a revocable per-user hash-only token.
- Adds opt-in Gmail/approved-IMAP mailbox discovery via verified TLS, encrypted app passwords, read-only search/fetch, UID cursors, 40-message batch limits, 14-day initial search and 15-minute periodic background checks.
- Adds Package Tracking preferences, mailbox connection status, manual check and disconnect controls in the existing 1.5 alpha UI.
- Keeps existing RecipeCove and meal visibility semantics; no changes to regular calendar records or meal data.

## Installation and upgrade

- For an existing v1.5.0-alpha.4 installation, apply this alpha update to **the same persistent database and data volume**. Do not switch to v1.4.11.
- Schema migrations `041_package_tracking.sql`, `042_package_inbound_tokens.sql`, and `043_package_mailboxes.sql` are added on startup in order. Existing data is not rewritten by package migration.
- Make a database/data backup before testing any alpha build. The independent `docker-compose.alpha.yml` still provisions isolated alpha volumes and must not be pointed at stable volumes.
- Package Tracking and automatic mailbox scanning require separate opt-in actions.

## Explicit limitations

Amazon/USPS/UPS/FedEx personal-account passwords are not supported; carrier sites are linked externally. Carrier API polling and Microsoft/Outlook OAuth are not yet supported. IMAP app passwords must be enabled by the mailbox provider; Gmail app passwords are only available on eligible accounts. Imported-email delivery dates are unverified estimates, not carrier scans. Native Android package screens are not included.

See [Package Tracking](../PACKAGE_TRACKING.md) for details.
