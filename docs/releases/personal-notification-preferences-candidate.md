# Calden — Personal notification delivery preferences (development candidate)

**Unreleased additive development.** Uses Calden's existing persistent notification inbox and existing live WebSocket/push paths. Does not introduce a second notification worker, Firebase dependency, or Android UI.

## Implemented source behavior

- Every account has private notification delivery settings, saved in PostgreSQL migration 036 with backward-compatible defaults.
- Per-person choices for live delivery, optional push delivery, enabled existing notification types (assigned events, shared events, Bill Pay review) and optional quiet hours.
- Quiet-hour comparisons use the household's configured IANA timezone and support overnight windows (e.g., 22:00–07:00).
- Live WebSocket messages and queued push delivery are filtered by current preferences and current permissions. Queued messages remain in durable inbox when delivery is not permitted.
- The existing REST inbox remains available and retains all authorized notification history; quiet hours and push toggles do not delete records.
- Children can access these preferences only when their guardian has enabled the Notifications module; existing child event/bill privacy checks remain.
- A personal settings form under **My reminders**, separate from administrator household settings, saves preferences by authenticated user ID.

## API contract

`GET /api/me/notification-preferences`
`PUT /api/me/notification-preferences`

JSON body:
```json
{"push_enabled":true,"live_enabled":true,
 "enabled_kinds":["event_assigned","event_family","bill_review"],
 "quiet_start":"22:00","quiet_end":"07:00"}
```
Both quiet fields can be null to disable quiet hours. An empty `enabled_kinds` array is valid and suppresses push/live messages while preserving the inbox.

## Known boundaries / acceptance gates

- **Event-specific lead times** are still configured on event reminders, not overridden by this personal preference API.
- New school/pet/maintenance reminders are not yet generated by Calden; these future types are not shown as functioning notification switches.
- Push provider registration and Android notification behavior remain to be tested with a real device; permission/battery recovery is not claimed completed.
- Full Go unit tests, PostgreSQL migration/quiet-hour checks, websocket reconnection, and push-lease concurrency checks are outstanding.
- Verified source-level client syntax, authenticated routing, and notification transport contracts only. 
- Stable production version remains **1.4.8** pending the full release acceptance round.
