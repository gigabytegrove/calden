# CalDen 0.1.0-alpha11.1

This hotfix corrects a calendar rendering bug that made some imported all-day events look duplicated on consecutive days.

## Root cause

iCalendar `DTEND` is exclusive.

For example:

```text
DTSTART;VALUE=DATE:20261006
DTEND;VALUE=DATE:20261007
```

is a one-day event on **October 6 only**. October 7 is the exclusive end boundary.

CalDen's day-overlap check used `event.end >= day.start`. That incorrectly included an event again when its end was exactly midnight at the start of the next day.

The result was one stored all-day event rendering on both its real date and the following date, which looked exactly like duplicated calendar data.

## Fix

Alpha11.1 changes calendar overlap handling to half-open ranges:

```text
[start, end)
```

The browser calendar and server event-range queries now both treat an event that ends exactly at the beginning of a day as **not occurring on that day**.

This fixes one-day Google/iCalendar all-day events showing twice across consecutive dates.

## Duplicate repair

Alpha11's in-place Google duplicate repair remains available for cases where the database actually contains multiple imported event rows sharing the same Google UID.

Do not use duplicate repair merely because an all-day event appeared on two adjacent dates. Update to Alpha11.1 first and verify the calendar again.

## Validation

Browser CI creates a one-day all-day event whose end is exactly midnight the following day and verifies the event title renders exactly once in the calendar.

Existing Bill Pay, Google import/repair, recurring-event, notification, backup/restore, and Docker deployment tests remain enabled.
